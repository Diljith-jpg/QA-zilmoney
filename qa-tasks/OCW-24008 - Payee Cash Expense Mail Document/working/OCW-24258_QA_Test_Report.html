Task Overview

OCW-24008 moves the Payee, Cash Expense, Document Mail and Document Mail History view pages to the V4 detail-panel pattern used by Payment Out and Payment In. The four pages were tested in Chrome on the OCW-24008 dev build: panel open and close, header and More Actions, every detail card and tile, comments and attachments (including validation and deletion), payee-type labels, empty states, expand / collapse, dark theme and typography against Payment Out. The panels match the V4 pattern, keep every existing action, and render identically to Payment Out. One low-severity defect was found. Responsive widths could not be tested because the browser window could not be resized, so the result is QA Blocked until that check is run.

Issue / Requirement Description

  • The Payee, Cash Expense, Document Mail and Document Mail History view pages used the old UI.
  • Requirement: follow the latest UX design, use the existing /v4-detail-panel structure, and stay consistent with the Payment Out and Payment In view pages.
  • Constraint: no change to existing business logic, API behaviour or functionality.

Updates / Changes Implemented

  • Payee: V4 panel with name, Added date and location in the header; Send / Receive; More Actions with Edit and Delete; information, summary, bank account and send / received cards; Contacts, To-dos, Comments, Attachments and Audit trail tiles.
  • Cash Expense: header with amount and Expense / Income badge; Clone, Get receipt and Send proof buttons; More Actions with Edit and Delete; details card with a highlighted Total cash row; Payee summary; Activity log, Comments, Attachments and Last 10 transactions tiles.
  • Document Mail: header with title, status badge and Added date; Mail and Download buttons; More Actions with Edit and Delete, disabled unless the status is New; Tracking details, Mail activity log and Comments tiles.
  • Document Mail History: V4 table page whose view opens the same Document Mail panel.
  • Comments and attachments now use the shared V4 list components with inline validation and in-app delete confirmation.

Testing & Verification

Payee

  • Verified that the panel opens from the list eye icon and closes with the close button, the Escape key and a click on the overlay, the same as Payment Out.
  • Confirmed that More Actions shows Edit and Delete (Delete in red) and closes without action when clicking outside it.
  • Confirmed that Edit opens the prefilled Update Customer modal and saves ("Payee Updated."), and the grid and panel refresh; after the save the header loses its Added date until the panel is reopened (BUG01).
  • Confirmed that the section label follows the payee type (Customer information / Employee information) and that missing fields show "—" and zero totals show $0.00.
  • Confirmed empty states for bank accounts, payments, contacts, comments and attachments, and that bank account numbers are masked to the last four digits.

Comments and attachments

  • Confirmed that an empty or whitespace-only comment is rejected with "Enter a comment before posting." and nothing is posted.
  • Confirmed that a valid comment is added with author and time, and that HTML typed into a comment is displayed as plain text, not rendered.
  • Confirmed that a 6 MB file is rejected with "Maximum file size is 5MB", a .txt file uploads, and delete asks for in-app confirmation before removing it.

Cash Expense

  • Verified the header, action buttons, details card, highlighted Total cash row, Payee summary and four tiles for both an Expense and an Income record.
  • Confirmed that the Payee summary total ($304.00) matches the payee's transactions in the list, and that every action of the previous panel is still available.
  • Confirmed that the typography of the Cash Expense panel is identical to the Payment Out panel (font family, size, weight, colour, button height and radius).

Document Mail and Document Mail History

  • Confirmed that Edit and Delete are disabled for a Pending document and enabled for a New document.
  • Confirmed that a comment added on a document is still shown after closing and reopening the same document, and that it can be deleted.
  • Verified that Document Mail History uses V4 table styling and opens the same Document Mail panel.

Layout, theme and network

  • Confirmed at 1920 px that the compact panel is 640 px and the expanded panel is 60 % (1150 px) with two-column cards, and that cards collapse and expand independently.
  • Confirmed that the Document Mail and Cash Expense panels use the dark tokens in dark theme (cards #1C293C, text #F8FAFC, labels #94A3B8, no shadow).
  • Confirmed that opening a panel calls only existing v4 endpoints with encrypted IDs, all returning 200, with no console errors.

Open Points & Observations

  • Blocked: responsive widths were not tested — the Chrome window is maximised and could not be resized from the extension. Needs a run in DevTools device mode or an un-maximised window.
  • Design values: the plan's font sizes (from the design file) are about 1 px smaller than the shared V4 implementation, but the new panels match Payment Out exactly. Confirm which one is the target.
  • Expanded state: the plan expects the expanded panel to be remembered after reload; the shared detail panel resets to compact on every open by design.
  • Print: the dev notes list Print in the Cash Expense More Actions; the build and the previous panel do not have it.
  • Attachments list shows the storage path (allattachments/payee/…) instead of the file name.
  • The payee Audit trail does not show a newly added comment until the panel is reopened.
  • After Escape closes the ⋮ menu, a further Escape does not close the panel until the panel is clicked.
  • Unchanged data, noted only: Document Mail created time differs between list and panel (time zone); Last 10 transactions dates use the created date; overdue and done to-dos share the same strikethrough style.

Conclusion

The Payee, Cash Expense, Document Mail and Document Mail History view pages are on the V4 detail-panel pattern, keep every existing action, handle comments, attachments and empty states correctly, and match the Payment Out view in typography and behaviour, in light and dark theme. One low-severity header defect is open. Responsive behaviour could not be verified in this run, so sign-off waits on that check; if it passes, the task can move to QA Pass with the low-severity defect deferred.
