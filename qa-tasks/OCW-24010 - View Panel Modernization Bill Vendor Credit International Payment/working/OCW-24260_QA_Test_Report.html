Task Overview

The task restyles five view pages as V4 detail side panels. Each panel was opened from its data table on the staging feature build and checked against the reference UI, or against the Payment Out panel where the reference has no design. The checks covered layout, actions per record status, tiles, expand/collapse, dark mode and typography, and the non-destructive actions (Pay, Edit, Clone, Send proof, comments, links) were run end-to-end. All five panels render in the new design and the tested actions work. A few small differences from the reference were found in the Bill and Vendor Credit action menus; QA reviewed them and accepted them. The task passes QA.

Issue / Requirement Description

  • The Bill, International Payment, Vendor Credit, Webhook Log and API Log view pages used the old layout.
  • Requirement: Redesign them per the linked UX task using /v4-detail-panel as the reference, matching Payment Out / Payment In, reusing V4 components, and keeping spacing, typography, actions, responsive behaviour and panel interactions consistent.
  • Constraint: Existing business logic, API integrations and functionality must be preserved unless the UX task changes them.

Updates / Changes Implemented

  • Bill: right-side drawer with amount + status badge, Invoice ID / Payee, status-based actions (Pay / Print / Unvoid + ⋮), Bill Details card with Bill Total highlight, Vendor Information (Bill From / Bill To), Line Items (credit applied) when present, and Audit Logs / Comments / Attachments tiles.
  • International Payment: "Payment Details" drawer with Clone and Send proof, Transaction details, Transaction ID strip, Statement table, Beneficiary (Details / Bank Details tabs), and Comments / Attachments / Signed Receipt / Proof of Delivery tiles.
  • Vendor Credit: drawer with Credit details, Vendor details (Open payee), Applied to bills and Audit logs / Comments / Attachments tiles; Edit + ⋮ according to status.
  • API Log: request line + response-status badge, Request details, Request / Response code blocks with Copy. Webhook Log: event type + status badge, Event details, Payload code block with Copy.
  • All panels: expand / collapse toggle, close, collapsible cards, and V4 colour tokens in light and dark mode.

Testing & Verification

Bill

  • Verified that the panel matches the reference layout: header with amount (Funnel Display 17 px / 700) and Due / Paid / Voided badge, Bill Details rows, Bill Total highlight, and Vendor Information with avatars. Pay Status appears only in the expanded view, as in the reference.
  • Confirmed the actions per status: Due shows Pay + ⋮ (Print, Edit, Void, Delete, Mark As Paid); Paid shows Print + ⋮ (Delete); Voided shows Unvoid + ⋮ (Print, Delete). Clone Bill stays available from the row ⋮ menu.
  • Confirmed that Pay opens Send Payment pre-filled with the bill (amount, payee, memo "Payment for Bill 1120") and that Edit opens the Edit Bill modal pre-filled. Neither was submitted.
  • Verified the tiles: audit log with "Show 13 more"; comments (posted a test comment; an empty comment shows "Enter a comment before posting."); and the attachments list with Upload attachment.
  • Verified expand / collapse, collapsing a card, close and reopen, the sticky header while the body scrolls, and dark mode.

International Payment

  • Verified that every section and tile of the reference is present and in order. Transaction details, the Statement history and both Beneficiary tabs show record data. Signed Receipt and Proof of Delivery empty states use the reference copy.
  • Confirmed that Clone opens Send Payment pre-filled (amount, wallet, payee, International Payment, INR). Send proof opens the existing Send Payment Proof options (Print Receipt, Copy Link, Email, Download, SMS, WhatsApp). Nothing was sent.
  • Confirmed the expanded two-column layout and the Failed-payment state (red badge, Purpose row, full statement history).

Vendor Credit

  • Verified the panel for New, Partially Paid and Reconciled credits. New shows Edit + ⋮ (Void, Delete); no actions appear when the row menu has all actions disabled (Partially Paid); Reconciled shows ⋮ with Delete only. Mark As Reconciled stays available from the row ⋮ menu.
  • Confirmed that Edit opens the Edit Vendor Credit modal pre-filled, that Open payee opens the payee record, and that the Applied-to-bills reference opens the linked bill panel.

API Log & Webhook Log

  • Reached both through Settings › More › Developer Panel. Verified the request line + 200 (green) / 422 (red) badges, Request details, Request / Response toggle, and Copy ("Copied!").
  • Verified the Webhook Log panel: event type + Failed badge, Event details, payload JSON with Copy, and expand / collapse.

Consistency

  • Confirmed that all five panels use the same shell as the Payment Out V4 panel: icon, title/amount with badge and sub-line, expand ⤢ / close, action row, collapsible cards and tile tabs.
  • Responsive behaviour at smaller widths (1024 / 768 / 390 px) was verified manually by the QA engineer and looks correct.

Notes

  • Differences from the reference that QA reviewed and accepted: the Bill panel ⋮ menu has no Clone Bill, the Voided bill Unvoid button uses brand blue, and the Vendor Credit panel ⋮ menu has no Mark As Reconciled. Clone Bill and Mark As Reconciled remain available from the row menus.
  • No reference design was supplied for Vendor Credit, Webhook Log or API Log; these were checked against the Payment Out pattern.
  • Test data: one comment "QA test OCW-24010" was added to bill Invoice 1120.

Conclusion

The Bill, International Payment, Vendor Credit, Webhook Log and API Log view pages open as V4 detail side panels on the staging feature build, consistent with the Payment Out panel and the reference design. Their sections, tiles, expand / collapse, dark mode, responsive behaviour and tested actions (Pay, Edit, Clone, Send proof, comments, links, Copy) work as expected. Destructive actions (Void, Delete, Print, etc.) were not run in this session.
