Task Overview

V3 shows a payment's category but the V4 Payment Details screen did not. The build adds a Category row to the Payment details section of the V4 detail panel. QA opened 76 payments on V4 Payments Out: Check, ACH, Email/Mail check, Let Vendor Decide and International payments with many statuses, including voided ones. For each one, the category the panel's own API returned was compared with what the panel displayed. Every payment with a category showed the correct name. Every payment without one showed no Category row. Values matched the V3 Check List.

Issue / Requirement Description

  • Reported: the transaction category is missing from the V4 Payment Details screen, while V3 shows it.
  • Requirement: show the category on the V4 Payment Details screen when one is assigned, and the value must match the transaction's category.
  • Requirement: when there is no category, do not show an empty or misleading value.
  • Requirement: stay consistent with V3 and leave existing payment-details functionality unchanged.

Updates / Changes Implemented

  • The Payment details section of the V4 detail panel now has a "Category" row between Method and the next field, showing the category name.
  • The row is left out entirely when the payment has no category.
  • The row also appears in the expanded (full-width) detail view.

Testing & Verification

Category shown and accurate

  • Verified that an ACH payment (ref 144) shows "Category: Consulting", which matches its API category.
  • Verified that checks show their own categories: "fgh" (900208, 2231312), "zil bank" (ref 1022), "realm estate" (ref 1022 and 1024) and "zil wallet" (ref 1024).
  • Confirmed that the check and zil-payment detail responses carry the same category ID and name, and the panel shows that name.
  • Confirmed that a voided/canceled check (2231312) still shows its category.
  • Confirmed that the expanded detail view shows the same Category row.

No category

  • Verified that payments with category: null (68 of the 76 opened) show no Category row and no blank or placeholder value.

Accuracy sweep

  • Confirmed that the panel category matched the API category for all 50 payments on page 1 of the All tab, and for all 13 results each for reference 1022 and 1024. There were no mismatches.

V3 parity, styling and regression

  • Confirmed that V4 matches the V3 Check List Category column (900208, 2231312, 2231313 = fgh; 900214 = blank). The V3 check view page has no Category field; V3 shows the category only in the list.
  • Verified that the Category row uses the same typography as the Method row (Plus Jakarta Sans, label 11px/400, value 11px/600) and is readable in dark mode.
  • Confirmed that the other panel content still renders: Reference ID, Transaction ID, Method, Source, Memo, check preview, status timeline and payee details.

Conclusion

The V4 Payment Details panel now shows the transaction category whenever one is assigned. The value matches the category on the transaction and in V3. The row is hidden when there is no category. This holds in both the side panel and the expanded view, and in light and dark mode. Other panel content is unchanged.
